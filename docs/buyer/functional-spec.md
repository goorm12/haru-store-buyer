## 회원
### AUTH-02 프로필 수정·로그아웃 — B11

- 이름·연락처 수정 시 형식을 검증하고 저장 결과를 표시한다.
- 새 예약에 최신 프로필을 사용한다. 기존 예약의 예약자 스냅샷을 일괄 바꾸지 않는다.
- 로그아웃 시 해당 세션을 종료하고 기기의 회원 푸시 연결을 해제한다. 다른 기기 로그아웃 여부는 세션 설계 사항이다.
- 세션 만료 시 로그인 안내 후 원래 화면으로 복귀하고 변경 요청을 자동 중복 실행하지 않는다.

**검수:** 로그아웃한 기기에서 개인정보 API 접근이 거절되고 다른 사용자로 로그인해 이전 예약을 볼 수 없다.


## 상점
### STORE-01 상점 검색·조회 — B02/B05

- 비회원도 상점명으로 검색하고 상점명·주소·소개·픽업 운영시간·연락처를 조회한다.
- 검색 결과 없는 경우 검색어 수정 안내, 오류인 경우 재시도 제공. 결과 없음과 통신 실패를 구분한다.
- 정상 상점과 공개 상품만 일반 검색에 노출하는 기본안을 사용한다.
- 제한·폐점 상점의 기존 예약자는 예약 상세에서 당시 픽업·문의 정보를 계속 확인한다. 정상 판매 중처럼 표시하지 않는다.

**검수:** 제한 상점은 신규 예약할 수 없지만 기존 예약의 안내가 사라지지 않는다.


### STORE-02 저장·기본 상점 — B03, P03

- 로그인 회원만 저장·해제 가능. 같은 상점을 중복 저장하지 않는다.
- 기본 상점은 저장한 정상 상점 중 구매자가 직접 지정한다. 한 회원에 최대 1개다.
- 최초 저장만으로 자동 기본 지정하지 않는 구현안을 사용하고 지정 버튼을 제공한다.
- 앱 진입 시 기본 상점 유효성 확인 → 유효하면 해당 상품 목록, 없으면 상점 선택 화면.
- 기본 상점 저장 해제·폐점·접근 제한 시 기본 지정을 해제하고 재선택을 안내한다. 임의 대체하지 않는다.
- 다른 상점을 구경해도 기본 상점이 자동 변경되지 않는다.

**검수:** 일반 상점 전환과 기본 상점 변경이 구분되고, 기본 지정은 서버에서도 1개로 유지된다.


## 상품 조회
### LIST-01 구매자 목록·상세 조회 — B04/B05

**구매자 표시:** 대표 이미지, 상품명, 판매 단위, 원화 단가, 접수 상태, 1인 한도, 예약 마감, 픽업 가능 날짜·운영시간·장소, 직접 취소 제한과 마감.

- 구매자는 공개 상품만 조회한다.
- 신규 예약 가능 → ‘예약하기’. 유효 예약 있음 → ‘내 예약 보기’ 및 변경 안내. 픽업 완료 이력 있음 → 같은 공구 재구매 불가 안내.
- 작성 중·숨김·취소·제한·마감·품절은 신규 예약 금지. 기존 예약의 접근은 유지한다.
- 품절은 남은 수량 0 표시이며 새로운 공구 상태를 만들지 않는다.
- 기본 목록은 최신 공개 순, 페이지 단위 조회를 구현 기본안으로 사용한다.

**검수:** 목록에서 접수 가능했어도 상세·확정 시 최신 상태를 재검증한다.


## 8. 구매자 예약 기능

### RSV-01 예약 생성 — B06/B07, P04~P08

**입력:** 공구 ID, 정수 수량, 픽업일. 예약자 이름·연락처는 프로필에서 확인한다.

**사전 표시:** 판매 단위·단가·예상 금액, 상점·주소·픽업 시간, 개인 한도, 취소 제한, 변경·취소 마감. 당일 예약이면 ‘오늘 예약은 변경·직접 취소할 수 없습니다’ 안내.

**서버 처리:**

1. 세션·회원 이용 상태 확인.
2. 공구·상점 접근 상태, 공개 여부, 취소·접수 중단 여부 확인.
3. 같은 구매자·공구의 유효 예약 및 픽업 완료 이력 확인.
4. 전체 접수 기간과 선택 픽업일·당일 마감 확인.
5. 수량·전체 잔여·취소 제외 개인 한도 검증.
6. 최신 단가·정책으로 요청 전 표시와 차이가 있으면 갱신 후 구매자 재확인 요구.
7. 원자적으로 수량 확보와 예약 생성. 예약 확정·미결제 저장.
8. 예약번호·스냅샷·이력·알림 이벤트 저장 후 성공 응답.

- 성공 즉시 확정, 판매자 승인 없음. 실패 시 수량만 점유되거나 예약만 생성되는 부분 성공 금지.
- 화면상 금액 계산만 믿지 않는다. 서버가 정수 단가×수량 계산.
- 유효 예약 있음 → 기존 예약 화면. 취소 후 재예약은 새 예약번호로 생성하고 취소 이력 유지.
- 픽업 완료 후 같은 공구는 재예약 불가. 다음 공구는 별개다.
- 무제한 개인 한도도 전체 잔여보다 많이 예약할 수 없다.

**결과 화면:** 예약번호, 상품·단위·수량·금액, 픽업일·장소·운영시간, 현장 결제 안내, 내 예약 이동.

### RSV-02 내 예약 목록·상세 — B08/B09

- 본인 예약만 조회. 예정은 예약 확정, 지난 내역은 취소·픽업 완료·미수령을 기본 분류로 사용한다.
- 날짜가 지났어도 예약 확정이면 ‘픽업일 경과’ 표시로 남기고 자동 미수령 처리하지 않는다.
- 현재 공구 정보보다 예약 당시 단가·정책·약속 정보를 우선 보여준다. 변경 공지가 있으면 함께 표시.
- 제한·숨김 상품도 본인 예약 상세 접근과 연락처·요청 경로 유지.
- 변경·취소 버튼 활성 여부는 서버가 반환한 허용 행동·사유로 표시하고 실행 시 다시 검증한다.

### RSV-03 수량 증가·감소 — B09

| 행동 | 조건 |
| --- | --- |
| 증가 | 예약 확정, 기존 픽업일 전날 마감 전, 신규 접수 열림, 잔여·개인 한도 충족 |
| 감소 | 예약 확정, 기존 픽업일 전날 마감 전, 직접 취소 제한 없음, 결과 수량 ≥ 1 |

- 감소는 공구 접수 중단·마감 후에도 허용된다. 직접 취소 제한이 있으면 감소 버튼도 차단한다.
- 증가 수량만큼 점유를 늘리고 감소분은 반환한다. 금액은 예약 당시 단가 기준이다.
- 차액을 온라인 청구·환불하지 않는다. 현장 결제 예정 금액만 변경한다.
- 같은 수량 저장은 변경 없음으로 처리, 중복 이력·알림 생성하지 않는 기본안.
- 동시에 판매자 취소·다른 수정 발생 시 버전 충돌 반환, 최신 예약 다시 조회. 실패하면 기존 예약 유지.

**검수:** 취소 제한 예약의 3→2 실패, 3→4는 기한·접수·한도 내 성공. 당일 모두 실패.

### RSV-04 픽업일 변경 — B09, P09

- 예약 확정이고 기존 픽업일과 새 픽업일이 모두 오늘보다 미래이며 기존 변경 기한 내여야 한다.
- 새 날짜는 공구가 유지하는 유효 픽업일이어야 한다. 신규 접수 마감과 별개로 허용한다.
- 접수 중단·마감은 날짜 변경만을 막는 이유가 아니다. 공구 취소·유효 날짜 삭제·예약 종료 상태는 차단한다.
- 수량·단가는 유지하고 새 픽업 스냅샷과 마감 기준·알림을 갱신한다. 직접 취소 제한 여부는 예약 당시 값을 유지한다.
- 날짜와 수량을 함께 저장하면 두 행동의 조건을 모두 만족해야 하며 전체 성공 또는 전체 실패로 처리한다.

### RSV-05 구매자 전체 취소 — B09

- 예약 확정·전날 마감 전·직접 취소 제한 없음 → 취소 확인 → 구매자 취소 → 수량 반환 → 이력·알림.
- 취소 후 복원 없음. 다시 접수 가능하면 새 예약으로 처리한다.
- 당일·취소 제한·종료 예약은 직접 취소 불가. 사유와 연락처·요청 경로 표시.
- 판매자 취소 및 법정 요청 처리는 구매자 직접 취소 제한과 구분한다.

### RSV-06 문의·법정 요청 — B09/B12/O03, P16

- 예약 관련 요청 유형, 요청 내용, 연락처·예약번호를 확인하고 접수한다.
- 접수는 예약 취소 승인이나 수량 반환을 의미하지 않는다. 예약 상태는 별도 승인·처리 시 변경한다.
- 판매자·운영자에게 해당 예약 범위에서 요청 조회·처리 사유 기록을 제공한다. 법정 권리 요청을 시간 경과만으로 자동 기각하지 않는다.
- 탈퇴 이후에는 로그인 필수 API 대신 운영 연락 경로를 안내한다. 본인 확인과 최소 정보 제공 절차는 출시 운영 설계에서 확정한다.


## 알림
### NOTI-01 안내 생성·조회 — B10

| 이벤트 | 생성 내용 |
| --- | --- |
| 예약 생성 | 상점·상품·수량·금액·픽업 안내 |
| 수량·날짜 변경 | 변경 전후 핵심 내용 |
| 구매자·판매자 취소 | 취소 결과, 판매자 사유 |
| 공구 취소 | 해당 유효 예약 취소 결과·사유 |
| 약속에 영향을 주는 변경 | 실제 처리된 변경 안내와 문의 경로 |

- 예약 변경 트랜잭션이 완료된 후 알림 이벤트를 처리한다. 푸시 실패로 확정 예약을 롤백하지 않는다.
- 앱 내 내역은 푸시 권한·푸시 전달 실패와 무관하게 조회 가능.
- 알림 선택 시 본인 예약 상세로 이동. 미로그인이면 로그인 후 이동. 권한이 없으면 정보 노출 없이 안내.
- 읽음 표시·최신 순·페이지 조회는 구현 기본안. 광고 알림 기능은 포함하지 않는다.


### NOTI-03 권한·설정 — B11

- 앱 알림 기능 설명 후 OS 권한 요청. 거절해도 예약 사용 가능.
- OS 권한과 서비스 알림 설정을 구분한다. 서비스 설정이 꺼져 있으면 푸시 중단, 앱 내 안내 유지.
- 기기 토큰 갱신·로그아웃·탈퇴 시 연결을 갱신한다. 이전 사용자의 푸시가 다른 로그인 사용자에게 가지 않게 한다.


## 신고 접수
로그인 구매자는 상점·상품 신고를 제출할 수 있다. 신고 접수는 자동 숨김·취소를 실행하지 않으며 플랫폼 관리자 검토와 구분한다.

### NOTICE-B01 공지 조회·댓글

상점 화면에서 공지 목록 진입 → 상세 조회 → 로그인 후 댓글 작성. 해당 상점 공지만 조회하며 신규 댓글·변경·삭제 결과를 반영한다. 비회원은 공개 공지만 읽을 수 있고 댓글 작성에는 로그인이 필요하다. 자신의 댓글만 수정·삭제한다. 공지 댓글은 예약 접수로 처리하지 않는다.

### INQUIRY-B01 비공개 문의

로그인 → 상점·상품·예약에서 문의 작성 → 제목·내용 확인 → 접수 → 내 문의 상세. 관련 예약은 본인 예약이면서 같은 상점인 경우만 연결한다. 다른 구매자에게 문의 목록·본문·첨부·답변을 노출하지 않는다. 작성자는 추가 메시지를 작성하고 본인 글을 수정·삭제할 수 있다. 문의 접수 완료와 예약 취소 완료를 혼동하지 않는다.

### COMM-NOTI-B01 공지·문의 알림

새 공지 알림은 저장한 해당 상점 공지 상세로, 판매자 문의 답변 알림은 본인 문의 상세로 이동한다. 로그인이 필요하면 로그인 후 대상에 복귀한다. 삭제되었거나 권한이 없으면 본문을 노출하지 않고 안내한다. 푸시 설정을 꺼도 화면 내 알림 확인은 가능하다.
